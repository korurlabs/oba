===========================================================================
 STORAGE DOMAIN — shrine/storage
===========================================================================

PURPOSE
-------
File storage management using Azure Blob Storage for the attachment
sub-domain (generic files). Uses a polymorphic entityType + entityId
pattern to link files to any domain entity without direct foreign keys.

ENTITIES
--------
Attachment (shrine.attachments):
  - url (TEXT): full URL in cloud storage
  - file_name (VARCHAR 255): original file name
  - content_type (VARCHAR 100): MIME type
  - file_size (BIGINT): size in bytes
  - entity_type (ENUM: StorageEntityType): type of owning entity
  - entity_id (UUID): ID of owning entity
  - organization_id (UUID): organization of the owning entity, set once on create
    from the request's checked organization; every read for a request filters on it

ENTITY TYPES
-----------
- TICKET: files attached to a ticket
- CHAT_MESSAGE: files sent with a chat message
- KALKAN_PAGE: evidence attached to a Kalkan page
- MAIL: files attached to an Otak mail
- RELATION: files attached to an Otak relation

ENDPOINTS
---------
| Method | Endpoint                                   | Auth  | Purpose              |
|--------|--------------------------------------------|-------|----------------------|
| POST   | /storage/attachments                       | GUEST | Upload attachments   |
| GET    | /storage/attachments?entityType&entityId   | GUEST | List by entity       |
| POST   | /storage/attachments/exists                | GUEST | Duplicate pre-check  |
| DELETE | /storage/attachments/{id}                  | GUEST | Delete an attachment |

Every endpoint needs the X-Organization-ID header (@RequiredUserAccess(GUEST)).
The parent must belong to that organization; ResourceAccessQueryService checks
the action's role, the app and the type's rules on it (READ, WRITE, DELETE).

CQRS
----
- AttachmentService (write): uploadAttachments, deleteAttachment
- AttachmentQueryService (read): listAttachmentsByEntity

INTEGRATION
-----------
Uses AzureBlobStorageService from connect/azure/ for cloud storage operations.
File names are sanitized (non-alphanumeric chars replaced with _) before upload.

CONVENTIONS
-----------
- Follows village CQRS, constants, LoggingService, and controller patterns.
- Attachment extends BaseEntity with UUID PK.
- DTOs are Java records.
- MapStruct mappers with componentModel = "spring".

HISTORY
-------

iText) were removed as dead code — they had zero callers across backend
and frontend. The shrine.photos table and the POI/iText pom dependencies
are cleaned up in later batches.
